# HOVEL Content Governance

## Primary Objective
Every content asset must move a reader one step closer to solving a problem and eventually to a product, service, or measurable outcome.

Flow:
Problem -> Evidence -> Content -> Lead Capture -> Solution -> Product -> Feedback -> Improvement.

## Stop Rules
Do not create content if:
- It duplicates an existing problem.
- It does not introduce a new stage in the customer journey.
- It cannot be connected to a future monetization path.

## Mandatory Content Checklist
1. Which problem does this solve?
2. Which existing content already covers this?
3. What is new?
4. What is the next CTA?
5. Which product/service does it support?

## Anti-Duplication Process
Before drafting:
- Search repository by keywords.
- Search by Problem ID.
- If overlap exceeds 30%, update existing content instead of creating a new one.
- Maintain one canonical article per problem.

## Content Types
- Awareness
- Diagnosis
- Solution
- Comparison
- Review
- Tool/Checklist
- Product

No new article should be published without passing this checklist.
